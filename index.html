Caderno de Exercícios: SQL

Evoluindo o Schema com Segurança usando ALTER TABLE

⚠️ Atenção: Formato de Entrega A entrega desta atividade deverá ser feita exclusivamente através de um arquivo .sql contendo todos os scripts de resolução numerados. Faça mudanças pequenas e testáveis (uma por vez) e sempre valide com dados reais ou de teste.

Parte 1: Ajustando a Estrutura Interna das Tabelas

1. Adicionar Coluna (ADD COLUMN) Questão 1
Contexto: Refatorar um schema significa mudar a estrutura para atender novos requisitos mantendo a consistência. O setor de vendas exigiu um novo controle. Escreva o comando SQL para adicionar uma coluna nova chamada codigo_barras do tipo VARCHAR(50) na tabela produto.
2. Alterar Tipo/Tamanho (MODIFY COLUMN) Questão 2
Contexto: O tamanho atual do nome dos produtos ficou pequeno. Uma boa prática é preferir ampliar limites antes de reduzir. Escreva o comando SQL para aumentar o tamanho permitido da coluna nome na tabela produto para VARCHAR(150) NOT NULL.
3. Remover Coluna (DROP COLUMN) Questão 3
Contexto: O sistema de código de barras físico será descontinuado. Escreva o comando para remover a coluna codigo_barras da tabela produto. Cuidado: essa operação resulta na perda de dado.
4. Simulação de Mudança de Escopo (Desafio) Questão 4
Contexto: Em um banco de dados que já possui registros, alterar tipos ou regras pode ser perigoso, pois pode falhar se existirem dados incompatíveis. Adicionar uma coluna NOT NULL exige valor para os dados existentes. Escreva um comando para adicionar uma coluna status_ativo na tabela produto utilizando DEFAULT para evitar erros de consistência.

Parte 2: Ajustando Relacionamentos e Integridade

5. Adicionar Relacionamento (ADD CONSTRAINT) Questão 5
Contexto: Em alguns casos, as chaves estrangeiras não são aplicadas na criação inicial. Precisamos adicionar a FK após as tabelas já existirem. Escreva o comando para adicionar a constraint fk_func_depto na tabela funcionarios, ligando departamento_id com a tabela departamentos(id) usando ON DELETE RESTRICT.
6. Remover Relacionamento (DROP FOREIGN KEY) Questão 6
Contexto: A arquitetura de dados mudou. Remova a FK da tabela funcionarios. Lembre-se do erro comum: se houver falha, pode ser o motivo de tentar dar DROP com um nome diferente do criado; se necessário, deve-se consultar o nome real no Workbench.
Lembrete Final: Entrega da Atividade Certifique-se de que as 6 questões de refatoração foram resolvidas no seu arquivo .sql.
